派工单全流程操作图

项目经理创建派工单 → 班组长接收并分派 → 工人处理提交 → 班组汇总 → 项目经理验收闭环
PM
项目经理
创建派工单、指定项目班组、抽查过程、最终验收或驳回重派。
SYS
系统
校验项目/班组绑定、记录轮次状态、通知相关人员、保存凭证。
TL
班组长
接收派工、选择本班组工人、审核过程和完工、提交班组汇总。
WK
工人
接收任务、开始处理、上传过程/完工照片定位、提交处理结果。
创建派工单
填写项目、班组、班组长、内容、位置、期限、验收要求和照片/定位规则。
PENDING_DELEGATION
校验并通知
校验项目可管、班组启用、班组长匹配；生成单号、创建首轮班组长记录。
通知班组长
班组长接收
班组长进入派工详情，确认任务要求，将本人派工记录由已分配改为已接收。
ASSIGNED → ACCEPTED
分派本组工人
从本项目、本班组成员中选择执行工人；系统创建工人派工记录并发送通知。
IN_PROGRESS
工人接收任务
工人从首页或消息进入详情，确认作业内容、位置、期限和安全要求。
ASSIGNED → ACCEPTED
开始现场处理
到达现场后开始处理；需要施工前照片时先上传 BEFORE 凭证。
ACCEPTED → PROCESSING
提交过程检查
按节点上传过程照片、描述和定位；系统生成待审核过程记录。
PENDING_PROCESS_CHECK
审核过程资料
班组长或项目经理按节点审核。通过回到施工，驳回要求工人整改重提。
通过 → IN_PROGRESS驳回 → PROCESS_REWORK
提交完工结果
过程检查全部通过后，上传完工照片和结果说明；所有工人提交后进入结果审核。
PENDING_WORKER_RESULT_REVIEW
审核工人结果
逐个审核工人完工凭证。全部通过后，班组长可填写本轮汇总。
通过 → 待汇总驳回 → 工人整改
提交班组汇总
填写班组整体处理说明，可补充汇总附件；系统通知项目经理验收。
PENDING_MANAGER_ACCEPTANCE
项目经理验收
验收前可发起抽查；通过则完成，驳回进入新轮次重分派或整改。
通过 → COMPLETED驳回 → PENDING_REASSIGNMENT
!
关键规则：派工必须绑定 项目 → 班组 → 班组长 → 本班组工人；班组长必须先接收再分派。 过程/完工照片、定位、版本号必须满足后端校验；验收驳回会进入新轮次，已完成或已取消不可继续操作。
依据 workerM 管理端、worker 工人端、workerback 派工接口与状态机整理
